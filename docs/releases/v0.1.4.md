Binaries for Linux (x86-64, arm64) and macOS (Apple silicon, Intel). Install or upgrade with
`curl -fsSL https://loadtable.osvauld.com/install.sh | sh`, then restart the daemon when it is idle.

This release also carries everything planned for 0.1.3, which was never published.

## Freeing disk space

`loadtable gc` shows what each checkout's build output takes on every machine, and what can go
(R-839):

```
Build output kept per machine
  laptop  42.4 GiB kept, 0 MiB can be freed
  nixos   195.1 GiB kept, 129.2 GiB can be freed
```

Each checkout is `in use` (a job queued or running), `active`, `idle` (no job in 14 days),
`merged` (its branch is in dev, main or master), `gone` (its working tree is deleted) or `old`
(output from an older layout). `loadtable gc --delete merged,gone,old` frees those on every
machine at once, and `--free PATH` frees one checkout whatever its state (R-840). Only build output
and the peers' synced copies are deleted: never a working tree, never a checkout a job uses, and
never the shared compiler cache or Gradle home. The MCP server has the same `gc` tool.

The window has a **Disk** tab: a card per machine, a row per checkout with its size on each
machine, tick boxes, and a Free button that asks before it deletes. After freeing, the cards show
what is left (R-844).

## Estimates are a range

An estimate now runs from the fastest recent passing run to the slowest:
`~5s–56s (median 16s) from 6 passing runs on laptop`. A warm cargo build takes seconds when
nothing changed and a minute when a crate did, so one number was wrong both ways. Runs that round
alike still show one number (`~4m`). A running job says `~3s–54s left`, then `up to ~26s left`
once it is past the fastest run, and only past the slowest `longer than recent runs (5s–56s) by
30s`, instead of "over the usual" for a run still inside what recent runs took (R-837). The CLI,
the MCP tools and the window say the same.

## Battery

- **Peer jobs run on battery above 30% by default** (R-834). At or below it, jobs from other
  machines wait, saying why ("mac is on battery at 25%"); an unknown charge counts as low. Set the
  line with `power.peer_jobs_min_battery_pct` in the machine policy (0 turns it off), or hold every
  peer job on battery with `power.peer_jobs_on_battery = "false"`.
- **Low battery is shown** (R-835) in that machine's `loadtable status`, beside it in the other
  machines' status, and in the window, where `battery 22%` replaces the machine's role.
- **`--anywhere` passes over a peer on low battery** whenever another machine can take the job,
  even a busy one; it still uses it when nothing else can run the job, such as an Apple build
  (R-836).

## Fixes

- **Jobs on a Mac find Homebrew's tools** (R-841). Under launchd a job's `PATH` lacked
  `/opt/homebrew/bin` and `/usr/local/bin`, so builds needing `pkg-config` or other Homebrew tools
  failed; both are now added after `~/.cargo/bin`.
- **Kotlin builds work on a peer** (R-843). A confined job may now write `~/.local/share/kotlin`,
  where the Kotlin compiler daemon keeps its run files, and nothing else under `~/.local/share`.
- **A long time left no longer overlaps its neighbour** in the window (R-838).
- The desktop window's title, top bar and app id say LoadTable (R-833).

## Releases

Merging to main now releases: a version with no tag yet is built, tagged and drafted, so nobody
tags by hand.

## Upgrading

Upgrade every machine: `gc` reports a peer only when that peer runs 0.1.4, and the battery state
reaches other machines only from 0.1.3 or later. Restart with
`systemctl --user restart loadtabled` (Linux) or `launchctl kickstart -k gui/$(id -u)/loadtabled`
(macOS) once `loadtable list --active` is empty.

The macOS binaries are not signed or notarized. The installer's binaries run as they are; an
archive downloaded in a browser needs `xattr -d com.apple.quarantine` on each binary.
