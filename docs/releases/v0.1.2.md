Binaries for Linux (x86-64, arm64) and macOS (Apple silicon, Intel). Install or upgrade with
`curl -fsSL https://loadtable.osvauld.com/install.sh | sh`, then restart the daemon when it is idle.

## The desktop window is in the release

`loadtable ui` now ships in the release binary, so the installer gives you the window too; no
source build needed. It shows every machine and its queue, each job's log, the history, timings,
the audit log and pressure stalls, and can cancel a job, move it up a queue class or drain the
machine. The window loads its graphics libraries only when it opens, so the same binary runs on a
headless worker; there `loadtable ui` says there is no display and points you to `loadtable status`
and `loadtable list --active` (R-832).

## Fixes

- **Confined cargo builds work on a Mac worker** (R-831). A job sent to a Mac failed with "could
  not canonicalize path" for each folder above the synced copy, because the sandbox closed the home
  folder to lookups too. The folders between the closed home folder and an opened one can now be
  looked up, not listed; the rest of the home folder stays closed. CI now runs the profile under
  the real `sandbox-exec`.

## Upgrading

Upgrade every machine; a Mac worker needs 0.1.2 for confined cargo builds. Restart with `systemctl --user restart loadtabled` (Linux) or
`launchctl kickstart -k gui/$(id -u)/loadtabled` (macOS) once `loadtable list --active` is empty.

The macOS binaries are not signed or notarized. The installer's binaries run as they are; an
archive downloaded in a browser needs `xattr -d com.apple.quarantine` on each binary.
