# `tasks` rewrite: requirements distilled from trial feedback

Source: the agent trial reports kept in `feedback/` (not published). That is 146 trial reports, excluding `TEMPLATE.md` and the directory `README.md`.
Citations use file basenames without `.md`. `n=` is the number of distinct files that raised the point. Positive reports that confirm an existing behaviour are counted too, marked "(+)". This keeps working behaviour from being lost in the rewrite.

Recurring IDs: `nixos` is the LAN worker/peer and `kurukkan` is the laptop. A "forwarded/offload job" has both a local ID and a remote ID.

---

## 1. Submission / CLI ergonomics

1. The `tasks run` command must end with exactly one stdout summary line, `job N <passed|failed|cancelled|interrupted> (exit X) owner=W [on HOST]`, so that `| tail -1` can recover the ID and the result. (callui-claude-11-run-output-and-logs, osv-blob-transfer-128-blob-transfer(+), safety-agent-25-29-cli-and-pressure-update(+), wave4-group-3761-placement-and-log-path, public-group-fixes-4005-nixos-timeout-and-truncated-logs; n=5)
2. A `tasks wait ID` command must block until the job is terminal and exit with the job's exit code, and it must never return immediately for a running job. (cleanup-core-3493-queue-wait-and-tail-logs, fast-start-301-325-offload-shell-wrapper-and-lost-approval, tests-core-3654-test-move, lead-runtime-4153-worker-load-and-placement, idle-cost-733-742-idle-daemon-and-ui-memory; n=5)
3. A `--detach` mode must print the job ID and return at once. A foreground client that hits the agent's 2- or 10-minute tool timeout must leave the job running and tell the caller to query the printed ID rather than resubmit. (split-transfer-3923-crate-split-transfer-wave, rt-w1-4031-peer-nixos-split-wave, present-wire-3562-offload-cargo-gradle, reroute-523-582-worker-offload-queue, public-group-s7-4008-retained-log-and-long-gradle, protocol-lan-resume-68-validation, sol-linux-worker-41-local-contracts, vp8enc-core-job9-18-desktop-vp8-encode, vp8enc-ui-26-28-codec-details, cleanup-desktop-3537-desktop-dead-code, lead-callnotif-3357-gradle-local, macos-setup-3890-3904-readonly-preflight(+), call-stats-panel-711-offload-gradle-and-local-cargo(+), cap-3mbps-405-407-408-417-offload-tests(+), pi-technical-docs-910-917-v038-validation(+), pi-tinline-site-3399-preview-restart(+), offload-client-115-ssh-offload-v0(+); n=17)
4. The client must print the job ID as soon as the job is enqueued, before approval or start. Any later client error must print `job N submitted but not <approved|started>: <recovery command>` and must not leave an orphaned queued job behind. (fast-start-301-325-offload-shell-wrapper-and-lost-approval, osv-lan-identity-56-lan-identity, tm-placement-57-nested-target-placement, wifi-est-55-59-disk-reserve-and-db-lock; n=4)
5. The client must retry transient socket errors (EAGAIN, a busy ledger) with backoff instead of exiting with `Resource temporarily unavailable (os error 11)`. (osv-lan-identity-56-lan-identity, osv-lan-identity-103-107-lan-peer, wifi-est-55-59-disk-reserve-and-db-lock, tm-placement-57-nested-target-placement; n=4)
6. Option conflicts and bad argv must be refused with the specific conflicting flags, the missing program name, or a hint naming the right tool. Examples are `--device` with `--run`, `./gradlew` not found, and `--offload` whose argv[0] is not `tasks-offload`. (lead-vp8enc-job22-24-review-reruns, lead-videosim-3477-3478-android-peer-build, lead-rotation-off-882-887-offload-tests, lead-gcallmic-3373-anywhere-frame-too-large(+); n=4)
7. Cargo `-j` handling must be consistent across job classes, plans and hosts. It must either clamp or refuse, and it must validate before source sync or before a plan starts, never after a long build. (hd-suggest-427-428-456-offload-jobs-cap-and-libclang, lead-runtime-4263-steps-build-run-split, lead-rotation-off-882-887-offload-tests, macos-platform-3888-native-primitives; n=4)
8. A remote command written as a shell interpreter (`sh -c '...'`) must not bypass argv checks such as the `-j` cap. The command must be refused, or the check must require an explicit flag. (fast-start-301-325-offload-shell-wrapper-and-lost-approval; n=1)
9. The first client line must print the resolved absolute cwd. (wifi-est-55-59-disk-reserve-and-db-lock; n=1)
10. On submission, the client must list other live or queued jobs in the same cwd, with their IDs and owners. (osv-lan-identity-56-lan-identity, osv-lan-identity-103-107-lan-peer, fix-cli-185-cli-output(+), pi-docs-3407-3408-status-table(+), pi-site-3474-3475-integrated-release-check(+), pi-site-3546-3548-ticks-preview(+), public-group-s6-3937-3939-desktop-check-test-clippy(+), public-group-s6a-3951-3952-peer-admission-and-hung-oom(+); n=8)
11. A locally placed job must warn "runs in your LIVE cwd: do not edit until it finishes". `tasks list` must flag a job whose tracked files changed after it started. (public-group-fix-3957-3963-live-cwd-placement, worker-package-476-553; n=2)
12. The client must not fail the job, or show it as failed, when its own stdout is closed (SIGPIPE/EPIPE, e.g. `| head`). It must exit with the job's real code. (fix-ops-165-198-portability-tmp-usage, vp8enc-core-job9-18-desktop-vp8-encode, pi-whitepaper-745-747-site-preview; n=3)
13. At submit, the client must warn about in-job pipes that will block-buffer output, such as `| grep` without `--line-buffered`. (lead-runtime-4184-laptop-placement-and-silent-log; n=1)
14. Every subcommand, including `tasks logs --help`, must print help and exit 0. Installed docs and the CLI must agree; for example, `list --active` was documented but rejected by the installed release. (split-wave1-3646-elided-log-middle, split-wave5-3869-elided-log-recurs, worker-desktop-233-portable-desktop-offload; n=3)
15. The job cost class must be correct or documented. Plain local `cargo test` was shown as `cpu_simulation`. (callui-claude-11-run-output-and-logs; n=1)

## 2. Admission & slots

1. No admission-slot lock FD may be inherited by any process that outlives its job. This includes sccache servers, `adb fork-server`, autostarted `tasks` daemons and fixture daemons. Every slot FD must be close-on-exec, and helpers must be started outside the job's lease. (lease-leak-532-161-sccache-holds-compile-lease, worker-package-476-553, health-alerts-502-577, worker-device-76-86-286-299-adb-server-lease-and-test-phone, peer-iroh-386-416, restart-survival-592-632-restart-survival; n=6)
2. When a slot is busy with no ledger holder, `admission`, `list` and the waiting job's log must name the real holder. That means the pid, the command, its `TASKS_JOB_ID` if any (and whether that job ended), and legacy non-ledger flock holders (`build_android.py`). (lease-leak-532-161-sccache-holds-compile-lease, worker-device-76-86-286-299-adb-server-lease-and-test-phone, osv-blobs-237-queue-wait-and-iroh-offload, extractor-job-8-standalone-trial, peer-iroh-386-416(+), notif-fix-481-android-unit-tests(+), consent-links-454-473-core-tests-and-checks(+); n=7)
3. Lock holders must be observed without taking the lock (via /proc/locks or fdinfo). The coordinator must never steal a lock or kill an untracked holder, and it must reap orphan holders of jobs that ended more than 60 s ago, logged as `ORPHAN of job N`. (restart-survival-592-632-restart-survival, lease-leak-532-161-sccache-holds-compile-lease, macos-owned-groups-not-submitted-lease-cleanup; n=3)
4. A job that is approved but not started must always show its reason in `list`, `logs` and `admission`. Possible reasons are offload slots held (budget plus holder IDs), operator drain, ledger lock held by pid, waiting for worker pickup, or a peer blocker. (cleanup-core-3493-queue-wait-and-tail-logs, integrate-594-626-osvauld-foundation-merges, lead-videosim-3406-remote-approved-stall, macos-coordinator-3885-3911-preparation, public-group-s2-3891-offload-cold-rerun, public-group-s34-3912-queue-blocked-by-hung-forward, split-wave2-3674-ledger-locked-stall, split-wave3-3700-misattributed-client-lines, tests-integration-3677-long-offload-queue; n=9)
5. A job that only waits on a peer and uses no local slot must not block the scheduler from claiming further approved jobs. (public-group-s34-3912-queue-blocked-by-hung-forward; n=1)
6. SQLite busy or locked conditions must be retried with backoff in the client, worker and supervisor. They must never interrupt, fail or cancel a waiting or running job. (codec-tuning-586-offload-gradle-hang-after-failure, hwdec-cost-48-58-disk-reserve-and-db-lock, tm-placement-57-nested-target-placement, wifi-est-55-59-disk-reserve-and-db-lock, split-wave2-3674-ledger-locked-stall, tests-integration-3677-long-offload-queue, present-wire-3562-offload-cargo-gradle, lead-runtime-4153-worker-load-and-placement; n=8)
7. A coordinator failure before the command started must be recorded as a distinct infra phase ("never started, resubmit is safe") with no command exit code, not as an ordinary `failed` exit 1. (split-wave2-3674-ledger-locked-stall, hwdec-cost-48-58-disk-reserve-and-db-lock; n=2)
8. Approval and execution intent must survive a daemon restart or reboot. Any `tasks` command must start the daemon and run approved jobs without a manual `start-worker`, unless the operator stopped the worker. (restart-survival-592-632-restart-survival; n=1)
9. The `tasks drain` command must stop new admission for safe restarts, and the drain and the job it waits on must be visible in `list`, `status` and the client. (restart-survival-592-632-restart-survival, macos-coordinator-3885-3911-preparation, public-group-s2-3891-offload-cold-rerun, lead-runtime-4263-steps-build-run-split(+); n=4)
10. The offload class must use its own slots, hold no run or compile slot while waiting, and ignore host CPU and memory-some PSI. It must keep the memory floor and the disk reserve. (fix-reliability-214-busy-ledger-client-offload, offload-slot-266-277-offload-admission-class, worker-device-76-86-286-299-adb-server-lease-and-test-phone(+); n=3)
11. A second offload from the same checkout must wait without holding an offload slot. It must show a phase such as `waiting_checkout (N)` that names the job it waits on, and this behaviour must be documented. (public-group-3857-anywhere-ran-local-j2, lead-videosim-3406-remote-approved-stall, rate-recovery-136-225-local-and-offload, wave4-group-3761-placement-and-log-path; n=4)
12. Run-class and device-class slots must be granted independently of the compile slot, and compile waits must be FIFO with visible holder and waiter per slot. (osv-worker-source-54-source-contracts(+), sol-linux-worker-41-local-contracts(+), macos-handover-3896-3897-template-validation(+), claude-android-targets-43-49-phone-test(+), ui-v2-335-358-dashboard-offload-and-toolchain(+), mcp-placement-425-434(+); n=6)

## 3. Pressure gates

1. The disk reserve must be an admission wait, not a terminal failure after admission. It must be checked before or during queueing and shown in `tasks admission` (path, available, reserve). The job must start by itself when space returns. (hwdec-cost-48-58-disk-reserve-and-db-lock, osv-lan-identity-56-lan-identity, wifi-est-55-59-disk-reserve-and-db-lock, tm-placement-57-nested-target-placement, fix-disk-166-177-disk-reserve-placement, osv-lan-identity-103-107-lan-peer, notif-fix-481-android-unit-tests; n=7)
2. The disk reserve must be checked on the filesystem that actually receives outputs, and only when a new output link must be created. (osv-lan-identity-56-lan-identity, tm-placement-57-nested-target-placement, fix-disk-166-177-disk-reserve-placement; n=3)
3. While a job waits, the client and the log must print the current blocker reason, with the measured value and the threshold, at least every 30 s. (presence-activity-479-485-call-read-activity, android-back-swipe-426-pressure-and-query-output(+), call-start-port-588-589-623-offload-cancel-and-gradle-heap(+), callui-claude-31-36-new-worktree-gradle(+), fanout-fix-3797-fanout-busy-tests(+), fix-cli-185-cli-output(+), wifi-est-55-59-disk-reserve-and-db-lock(+), video-sims-636-offload-sim-suite(+), rate-recovery-136-225-local-and-offload(+), safety-agent-25-29-cli-and-pressure-update(+), macos-platform-3888-native-primitives(+), tm-cargo-jobs-132-134-cargo-jobs-cap(+); n=12)
4. Status and MCP snapshots must report blockers per class (`compile`, `run`, `offload`), not one compile-only `blocker`. (mcp-383-392, notif-fix-481-android-unit-tests; n=2)
5. All thresholds (minimum available memory, cache free, state free, PSI limits) must be configurable per host. `tasks admission` must report each threshold's effective value and source, and the defaults must not make a smaller host unable ever to admit (an 8 GiB floor on a 7.6 GiB worker). (tm-worker-portability-121-fresh-host, lease-leak-532-161-sccache-holds-compile-lease, safety-agent-25-29-cli-and-pressure-update; n=3)
6. On macOS, admission must use a reviewed native headroom policy (sysctl memory pressure, load, free and purgeable memory, statvfs). Native measurement results must be validated, with short structs rejected. Unknown or unsupported measurements must refuse rather than silently skip the gate. (macos-admission-not-submitted-native-candidate, macos-merge-not-submitted-dev-integration, macos-boundaries-not-submitted-headless, macos-foundation-not-submitted-worktree; n=4)
7. Light run-only jobs must not wait for long periods on host CPU PSI caused by other agents' compiles. The blocker must not flap without explanation. (offload-client-115-ssh-offload-v0, tm-worker-portability-121-fresh-host, status-stream-324-348; n=3)
8. When memory PSI rises during a job's own run (self-induced load), the job record must say so and suggest reducing test threads. (lead-runtime-4153-worker-load-and-placement, public-group-fixes-4005-nixos-timeout-and-truncated-logs; n=2)
9. If `/proc/pressure` is missing on Linux, admission must fail closed and say so. (tm-worker-portability-121-fresh-host; n=1)
10. Operator headroom guidance must include a read-only, ownership-aware inventory of RAM-backed /tmp that never deletes anything. (safety-agent-25-29-cli-and-pressure-update, fix-ops-165-198-portability-tmp-usage; n=2)

### 4a. Timing knowledge (design decision, 2026-10-22, user)

Most jobs repeat the same commands and test targets, so the system must learn their durations as it goes and use them for ETAs, splitting and placement.

8. Every job must get a **recipe key**: the normalized command (tool, subcommand, packages, test target or filter, features, profile and kind), ignoring `-j`, env order, owner and checkout path. Two runs of the same tests on any checkout share the key.
9. The runner must **timestamp every output line** and derive a per-phase breakdown from known tool output:
   - cargo: compile ends at `Finished`; each `Running <target>` up to its `test result: … finished in Xs` is one target's run time, plus pass/fail/ignored counts.
   - gradle (`--console=plain`): one entry per `> Task :x:y`.
   - Unknown tools give a single whole-job duration.
10. Durations must be stored per **(recipe key or target, machine, cache state warm/cold)**. ETA is the median, with p90 as the upper bound, of matching history on that machine. With no history, fall back to the same key on another machine scaled by core count, then to the kind's median, and always say which source was used ("ETA 4m from 12 runs on nixos").
11. A broad command must be **splittable automatically**. `tasks2 split cargo test -p X --features F …` runs `cargo test --no-run --message-format=json` once, lists the test executables, and emits a plan with one build step plus one run step per target, all with identical flags. Gradle splits per test task.
12. Split plans must be **scheduled longest-first from history** and placed so long targets go to the strongest free machine. Targets with no history are scheduled as long until measured.
13. `tasks2 stats` must show the slowest recipes and targets (median, p90, runs, fail rate and machine), what got slower recently, and how much time went to compile versus run. The UI shows the same model.
14. Probes (`true`, smoke tests) and failed-at-compile runs must not pollute a target's run-time history; cancelled runs are kept but marked.
15. A running job's progress must use the per-target history: "target 7/22 (lifecycle, usually 3m10s); ETA 14m".

### 4b. Repo run policy (design decision, 2026-10-22, user)

How a repo is built and tested is data that lives in the repo, not in agents' heads. Agents read it, and agents (not tasks) update it from measured history.

16. A repo may carry a **run policy** file (`.tasks/run-policy.*`, versioned with the code). It holds named suites, e.g. `core-tests` = these packages/features, split per target. Per suite it gives:
    - the exact flags, so every step shares one build;
    - split rules;
    - known long targets and placement hints, e.g. "needs xcodebuild" or "prefer nixos";
    - required tools;
    - what may be skipped for a quick check versus a full run.
17. `tasks2 suite run NAME` (and `tasks2 suite list`) runs a suite from the policy as a split, longest-first plan. Agents use suite names instead of hand-writing cargo or gradle lines.
18. `tasks2 policy show` prints the effective policy for the checkout. An agent's brief only needs "read `tasks2 policy show`".
19. `tasks2 policy suggest` analyses this repo's recorded history:
    - new or removed targets;
    - targets that got slow or flaky;
    - flags that differ between runs and cause rebuilds;
    - suites that would gain from a split.

    It prints a proposed policy diff with the evidence behind it (run counts and times). An agent reviews the diff and commits it like code.
20. tasks never rewrites the policy file itself. It validates it on load, rejecting unknown keys with a named error, and warns when a job's command contradicts the policy, e.g. different features from the suite's build, which forces a rebuild.
22. A job predicted short from history (e.g. a `cargo check` with a median under 1 minute) must not wait unbounded behind a CPU gate tuned for long builds. It gets a short-job lane, admitted on its prediction and audited. If it overruns its p90 by a set factor, it is reported. (observed 2026-10-22: v2 skeleton `cargo check`, job 4279, waited 17+ minutes on CPU PSI behind a release `cargo test`)
23. A job's working directory must be the checkout it builds. `tasks2 run` takes `--cwd DIR`, so agents never need `cd … &&` or `--manifest-path` from another checkout. (observed 2026-10-22: job 4279 was recorded with the main checkout's cwd while building v2 through `--manifest-path`)
21. Machine policy (slots, thresholds, reserves) stays separate from repo run policy. Machine policy belongs to the host owner; run policy belongs to the repo.

## Top 10 pain points (by number of files)

1. **Log elision hides results, and the full log is hard to reach** (§5.1-5.3): about 25 distinct files. Head and tail views drop per-target `test result` lines and panic messages, the notice is buried, and there is no `--full`, `--grep` or path. This caused repeated needless resubmits.
2. **Agent tool timeouts with no `wait` or `--detach`** (§1.2-1.3): about 20 files. Clients detach at 2 or 10 minutes, and agents write poll loops that are fragile or never end and burn daemon CPU.
3. **Opaque placement** (§7.1-7.2, 7.10): about 14 files. There is no stated reason, and silent `-j`→`CARGO_BUILD_JOBS=2` rewrites happen. Machine choice varies for identical commands, and the result line does not name the host.
4. **Approved-but-not-started with no reason** (§2.4-2.5, 2.9): about 11 files. Causes include offload slot exhaustion, drain, the ledger lock, a scheduler stuck on a forwarded job, and misleading `execution_enabled=false`.
5. **Remote state invisible locally** (§7.3, 10.4): about 10 files. A forwarded job shows `running` while the remote waits on PSI or the compile slot, or has hung.
6. **Android builds on the peer fail on environment** (§9.1-9.2): about 10 files. Causes are the Gradle heap (unsynced `gradle.properties`), missing x86_64 libaom, and missing flags; the documented command does not pass unchanged.
7. **Double or confusing exit status lines** (§5.4): 9 files.
8. **SQLite "database is locked" interrupting, failing or stalling jobs** (§2.6-2.7): 8 files.
9. **Disk reserve as a late terminal failure, invisible in `admission`** (§3.1-3.2): 7 files.
10. **Hung jobs after Gradle OOM holding slots for 1 to 2+ hours** (§6.1): 7 files. Tied with **leaked slot leases from inherited FDs** (sccache, adb, autostarted daemons; §2.1-2.2): 6 to 7 files, and with **verbose, unbounded `tasks list` JSON** (§1.1, 10.1-10.2): 7 to 11 files.
